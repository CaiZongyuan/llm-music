## Draft and failure promises

Saved Project/Asset/Score/Candidate/Version/Job records belong to FastAPI and can be reread. Unsubmitted Project text, native file selection, generation draft text, unsaved version names, selected playback and playback position are session state. Navigating or changing language/theme preserves the supported mounted draft; a full reload does not promise to preserve that session. A submitted Job route restores its input, and a persisted Candidate can copy its snapshot back into a new draft. A Candidate becomes a Version only after explicit save. The [generation guide](../guides/web-generation.md) states these limits in both languages.

The existing dedicated tests remain the evidence for hostile/duplicate/out-of-order WS hints, HTTP fallback, cancellation confirmation, explicit retry identities, unknown progress, OOM/model/workflow/readiness faults, damaged media, missing download bytes and lost save acknowledgements. The new restart case does not claim to rerun all those scenarios or real inference.
