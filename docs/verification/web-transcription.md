# Transcription Web verification

Issue: [#34](https://github.com/CaiZongyuan/llm-music/issues/34). Source baseline: `71e47211b0417463011adf9b4d80e21ab9da1798`. Confirmed layout/flows: `e2029719eab0e02d2e198f48fdd0f9e21ff360d6`, with Chinese/English and light/dark requirements in [the preview record](../ui/31-web-mvp-preview.md). The closed prototype is retained as source and was not restarted.

The feature owns Transcription and read-only Score routes. It consumes generated OpenAPI requests, shared Job hooks/queries/components, and existing Asset metadata/content helpers. It creates no polling, WebSocket, application server store, audio element, Score editor or Cover operation. Reference selection and submitted Job identity live in typed route search; saved Score identity lives in its route. All persistent data remains API-owned.

Score ABC comes from `ScoreRead.abc_asset_id`. MIDI is resolved only from the same producing `ScoreRead.job_id`, whose `result.score_id` must match the viewed Score. Generated scores show the absence of a Reference Audio or MIDI explicitly. Native downloads preserve registered filenames, media types and bytes; a failed file read keeps the Score and offers a retry. abcjs is loaded only when displaying notation.

The owned browser suite is `tests/browser/transcription.web.ts`. It uses the existing real FastAPI+CPU FakeRuntime harness with a new isolated data directory per run, and never proxies to Runtime8188. It checks four language/theme combinations, persisted Project/Reference/Job/Score relations, valid rendered SVG, native ABC/MIDI downloads, SHA256 and readable timed MIDI note events, reload identities, invalid/unsupported audio, missing file recovery and generated-score ownership. A temporary MIDI rename is confined to the identified test harness's own application directory and restored in `finally`; business HTTP responses are not mocked.

The additional `transcription-recovery.controlled.ts` suite and `transcription.playwright.config.ts` reuse #33's test-only injected CPU Runtime in unchanged production FastAPI/JobService/SQLite. Fixture endpoints change observations rather than mocking business HTTP replies. It exercises model missing, Runtime unavailable and stale readiness; held `transcribing` with unknown progress; accepted cancellation before terminal confirmation; cancelled→failed retry→completed retry; preserved original input snapshots and distinct attempt identities. Shared Monitor source is consumed from #33's commits `06556464` and `7ec2d9dd`.
