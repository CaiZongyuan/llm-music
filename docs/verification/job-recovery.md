## Behavior and ownership

The API persists original immutable inputs/provenance, attempt, Workflow snapshot, native graph and planned reference upload binding before native writes. ComfyUI recovery checks the original endpoint, client, graph, unique mapping and stored handle consistency. It restores the original Workflow snapshot instead of rebuilding it from a newer registry. Generate imports audio only from the frozen SaveAudio prefix. Fake recovery also requires its exact original proof and inputs. Current readiness applies to new submission; expiry does not erase accepted ownership or results.

Startup never dispatches `/prompt` or uploads Reference Audio. Even proven pending application work is only reconciled. Transcribe result validation can export/upload generated MIDI through existing score tools; this is distinct from original Reference Audio transfer and inference dispatch. One application worker observes/imports recovered work and new live work. Completed, failed and cancelled Jobs remain terminal. Whole-set result validation, unique result associations, commit-ack readback and file compensation use the shared result-import path.

The durable uncertainty budget defaults to 300 seconds, 30 confirmation attempts and polling from 1 to 10 seconds. The worker creates all missing startup-group windows together after metadata admission; existing windows remain untouched. Restart, events and reads do not renew an unknown deadline/count. A previously confirmed original gets one bounded verification at a later startup even if its former window elapsed during generation. The API consumes that probe durably before I/O. Uncertainty after that probe obeys the original budget. Startup sweeps unresolved siblings before known observations, and borrowed read-slice timeouts yield without declaring the known source unavailable. Cursor persistence uncertainty remains guarded within the same worker and re-reads committed state on the next sweep.
