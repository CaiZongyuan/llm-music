## Public boundary and durable ownership

Project and Reference Audio are read/written through FastAPI HTTP with Pydantic/OpenAPI. SQLAlchemy 2/Alembic own initial schema `0001_project_audio`; SQLite WAL, foreign keys and explicit BEGIN cover DML and DDL. Binary data is absent from database rows and remains in the configured application Asset store. Server-generated canonical Project/Asset UUID keys, scoped metadata and resolved filesystem containment reject cross-Project references, traversal/drive mappings and static Windows junction escapes. Filenames are display metadata only. Metadata/content/list reads report missing or incomplete files explicitly.

The new upload consumes no Runtime API or existing Runtime venv/helper. WAV verification uses the CPU standard library and all PCM frames; byte/hash/facts derive from original content. The 64 MiB/600-second budgets are explicit application policies rather than model capabilities. ASGI request-byte accounting bounds multipart input even without Content-Length, including a 64 KiB framing allowance.

File publication and metadata commit are distinct transactions. A unique private staging file is checked first; final creation is exclusive, copied/flushed/fsynced/closed before metadata commit. Successful import retains final and removes stage. On commit failure, rollback is attempted and a fresh connection reads back this exact Asset id. Only acknowledged rollback plus confirmed absent row permits final compensation. Durable row, rollback failure or readback uncertainty retains content and returns non-success with application id/recovery. Cleanup attempts only this operation's owned files; one failed cleanup does not prevent compensation of another eligible file. A crash may leave unregistered private files; no global scanning/deletion/GC is performed.

New actual consumers are the HTTP client/example, migration entrypoint, OpenAPI reader and isolated tests. No supported earlier application schema exists; empty baseline → initial head and repeated head startup are supported. Future generated Asset types need a deliberate schema/contract extension rather than pretending their formats are implemented now. Existing public Runtime contracts stay intact.

## Discriminating checks and early oracle

The first Project HTTP test failed because the new module did not exist, then passed with initial Project persistence. The first upload test failed at the missing route, then passed with original bytes/facts. The chunked multipart test initially accepted a legal small WAV plus excessive unused framing/field bytes; after bounded ASGI accounting it returns 413. Pydantic validation now uses the same public domain-error envelope as other failures.

The early non-author oracle identified a durable-commit/lost-acknowledgement counterexample: unconditional file deletion after a commit exception leaves a row pointing to missing data. Public HTTP tests inject an external SQLAlchemy after_commit exception and confirm the 503 response's Asset id remains readable/downloadable, including after app reopen. A second external DB event makes readback unavailable and still preserves content. A real SQLite BEFORE INSERT abort proves the confirmed-uncommitted path removes only the new final and leaves an earlier Asset intact. Filesystem obstruction and an external unlink failure distinguish write failure from incomplete owned cleanup. These are system-boundary faults, not patched application services or method-count assertions.

A separate initial migration counterexample interrupted DDL at assets table creation. Legacy SQLite transaction behavior left the earlier projects table durable; restart failed with “table projects already exists”. SQLAlchemy now disables legacy transaction control and emits explicit BEGIN; Alembic declares transactional DDL. The same failed-startup → restart public entrypoint passes with no partial business schema. Commit/readback/rollback fault cases continue to pass under the new transaction behavior. Unsupported revision startup refuses to migrate while preserving data; restoring the deliberately injected revision in the isolated test makes existing Project readable again. This fault restoration is not advice to stamp production databases.

True child API processes on independent loopback ports create/upload/read, stop, delete only their isolated temporary Runtime source, restart on the same database/storage and read the same Project/Asset/original bytes. A Windows junction counterexample redirects the stored Project directory outside Asset root; HTTP refuses content and preserves the target. Contract export runs without storage initialization. The API environment explicitly checks `find_spec('torch') is None` and is not the Runtime interpreter.
