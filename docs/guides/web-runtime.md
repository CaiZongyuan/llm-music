# 创作前检查服务、模型与任务

你已经为“雨后的散步”创建一个 [音乐项目](web-workspace.md)。如果音乐生成或参考转谱暂时不能开始，打开正式 Web 的 `/runtime`，先看哪项准备条件需要恢复。这里通过应用服务读取状态，不需要打开底层节点画布。

## 看懂当前准备状态 {#readiness}

1. 看“服务与创作准备”。应用服务与推理服务各有自己的状态；生成和转谱也分别显示准备结果。
2. 看“音乐模型”。缺失、下载中、已就绪、校验失败分别表示不同的文件校验事实。“无法取得当前状态”不能当成模型已就绪。
3. 展开“观测时间”，检查原始观测时间与事实来源。稳定模型和源码校验在实际绑定与文件仍匹配时保持可用，不按五分钟倒计时失效；来源时间照实保留。动态观测超过有限时间窗口会显示“观测已过期”，保留数值作为上次记录。
4. 选择“重新检查”。这只重新读取状态，不创建任务，也不下载模型或修改运行环境。

CPU 示例环境会明确标识。示例管线可用不代表真实 GPU 已经就绪，也不能作为音乐质量或推理性能证明。

## 判断设备与排队情况 {#facts}

“设备观测”显示 API 实际取得的 GPU 名称、显存与内存读数。显存按 GiB 和原始 bytes 显示。设备总量、空闲量和已用量包含其他进程；Torch 活跃或预留读数属于推理进程分配器。展开“更多内存读数与范围”查看其余读数，不把可用显存代理值当成纯空闲显存。

当前 API 不公开已加载模型身份，所以“已加载模型”显示未知。登记文件、校验通过和模型已加载是不同的事实；驱动、CUDA 或进程内存读数缺失时也不补成零。

“应用任务队列”来自保存的活跃 Job。查看排队、运行与任务标识，选择任务标识回到其 Project。刷新后仍从服务端读取同一任务。这个快照不代表底层全部 GPU 占用；只有一个已记录运行任务时才提供该运行任务标识。底层占用没有读数时显示未知。

“运行版本”展示实际观测；“版本与校验来源”提供登记的模型仓库、版本、文件、SHA256 与权重许可。登记源码版本是要求，不代替当前源码观测。权重许可与代码许可分别显示。

## 恢复后继续创作 {#recover}

模型缺失或下载未完成时，请由环境维护者准备登记权重并校验完整文件。校验失败时保留原文件，再检查正确版本和 hash。推理服务失联时先恢复服务。进程/监听、源码与模型文件未改变时继续使用原校验；条件改变后恢复实际条件并取得匹配证据。重新保存或读取记录不会更新原始校验时间。

应用读取失败时，页面显示错误和“重新读取状态”，不会把失败显示成空队列或旧的绿色准备状态。恢复连接后重新检查，再回到“雨后的散步”，保留原素材与创作目标。不要为排障重复提交创作任务。

## 了解使用设置 {#settings}

打开正式 Web 的 `/settings`。先查看当前创作范围，再按需查看“应用配置参考”。字段、环境变量名、默认值与规则来自 API 的 Settings 元数据。

**这些是声明默认值，不是当前进程的生效配置。** 启动环境可以覆盖它们；当前 API 不提供生效覆盖值或配置写入接口。页面只读，不能在这里保存服务器配置。音频接收上限也不等于所有音频都可用于转谱；具体创作表单与服务端仍检查当前支持的输入。

中英语言与亮暗模式使用工作台顶部的共同入口，跨页面和刷新保留。更多环境说明见 [应用配置参考](../reference/settings.md) 与 [Runtime API 指南](api-runtime-diagnostics.md)。

<summary>隔离浏览器验证</summary>

在仓库根目录准备 pnpm 依赖与独立 `services/api` uv 环境后运行：

```powershell
pnpm web:check
pnpm test:browser:check
pnpm --filter @llm-music/browser-tests exec playwright test --config web.playwright.config.ts runtime.web.ts
pnpm --filter @llm-music/browser-tests exec playwright test --config runtime.playwright.config.ts
```

第一组使用实际 FastAPI 和已有 CPU Fake Runtime，覆盖四种语言/主题组合以及真实未知读数。第二组在独立 Runtime seam 注入明确的 CPU 来源观测，覆盖模型各状态、缺读数、过期、失联、空/加载、HTTP 错误恢复与应用任务身份。没有替换生产 HTTP 响应；没有测量 GPU 或运行音乐推理。测试只启动自有端口、数据目录与进程，退出需要平稳关闭回执。真实 GPU 读数在阶段验收另行验证。

</details>
