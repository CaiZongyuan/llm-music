# 跟踪创作任务，取消并继续

在“雨后的散步”项目中，生成与转谱都形成持久创作任务。打开项目的“任务”，检查当前阶段、完成结果与失败原因。全局“任务”按项目显示同一批记录；项目名和创作输入保持原样。

## 读懂任务进展 {#progress}

任务只有等待创作资源、正在创作、已完成、未完成和已取消五种状态。正在创作时，页面显示应用已确认的音乐阶段，例如转谱、规划乐谱、合成音乐或保存结果。

“进度未知，当前只显示阶段”表示没有可靠的整个任务比例。页面不会用经过时间或阶段推测百分比。若应用提供实测进度，则显示真实读数。阶段来源丢失时，阶段可以回到未知；任务没有因此重新开始。

完成后选择“检查乐谱”；音乐生成也提供“试听生成结果”。这些入口随正式转谱/生成功能交付，在同一个工作区继续检查。生成完成先形成 Candidate，只有明确保存才成为 Version。

## 取消不再需要的工作 {#cancel}

1. 在目标任务选择“请求取消”。其他任务与已有素材保留。
2. 等待最终确认。“已提出取消”是意图，仍可能显示等待或正在创作。
3. 任务确认取消后才显示“已取消”。若完成先发生，则显示“已完成”并保留结果。

取消确认失败时，先“重新读取任务”，确认原任务是否仍活动。需要再次取消时，选择“再次确认取消”；操作仍指向原任务，没有改成全局中断。恢复提示不会引入第六种任务状态。

## 查看失败并明确重试 {#retry}

“为什么没有完成”提供领域原因与下一步。原输入和失败记录保留。恢复模型、创作资源或应用连接后，选择“创建新的重试任务”。新任务使用独立标识，沿用原输入，并关联原任务；没有覆盖旧记录。

重试创建是否成功尚未确认时，先“读取现有重试记录”。页面读取项目任务，找到新记录后提供其标识和入口；不会自动再次提交。若已知请求因所需模型等前提被拒绝，可恢复条件后再次明确重试。无法确认的创建意图在当前页面保持阻止，避免盲目重复工作。

## 断线或刷新后继续 {#recover}

实时更新断开时，页面继续从应用服务读取同一个任务，并尝试重连。HTTP 读取失败会显示错误，保留已经读到的记录；恢复连接后选择“重新读取任务”。已有结果、任务标识与已确认终态不会被旧消息变回正在创作。

刷新页面或重新打开同一个项目后，任务来自应用保存的记录。一个任务的独立入口是 `/projects/<PROJECT_ID>/jobs?jobId=<JOB_ID>`；这个地址只读取任务，不会再次生成或转谱。等待期间不要通过重新提交表单来恢复进度。

顶部可切换中文/English及亮暗主题。取消、失败和恢复说明同步切换；项目名、歌词与原始输入保持不变。

## 本地验证范围 {#verification}

按[工作区启动指南](web-workspace.md#launch)启动 Web 与 FastAPI。测试使用独立 CPU FakeRuntime 和 SQLite，验证页面行为、持久标识、断线恢复与取消/重试确认。控制用夹具接口只存在于浏览器测试服务器，不进入正式应用。CPU 结果不证明实际音乐效果、推理速度或真实 GPU 取消；真实 Runtime 验证由资源 owner 串行执行。
